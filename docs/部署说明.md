## 一、技术架构

```
浏览器 /admin  ──POST /api/publish──▶  Worker（/api/*）
                                        │
                                        │ GitHub Contents API
                                        ▼
                                  li1574/blog 仓库
                                        │
                                        │ 仓库变更触发构建
                                        ▼
                              Cloudflare 重新构建 → 上线
```

静态页面和 API 在同一个 Worker 里：

- `/api/*` 走 Worker 脚本（`worker/index.ts`）
- 其余请求直接由静态资源处理，不消耗 Worker 调用次数（靠 `wrangler.jsonc` 的 `run_worker_first: ["/api/*"]`）

## 二、日常发文

### 方式一：网页后台（推荐）

打开 https://blog.li1574.ccwu.cc/admin

1. 填发文口令
2. 填标题、摘要、标签、正文
3. 点发布，或按 `Ctrl / Cmd + S`

提交后会返回 GitHub 的 commit 链接。**如果接了自动构建，1-2 分钟后线上生效。**

其它操作：

- 下拉框可以载入已有文章修改，覆盖发布
- 勾「存为草稿」= `draft: true`，不进列表
- 文件名（slug）留空会用时间戳兜底，因为中文标题转不出有意义的英文 slug
- 页面下方的「精选文章」面板可以直接勾选，勾上的会出现在首页「精选」区（本质是改 frontmatter 的 `featured: true`）

### 方式二：本地写

```bash
cd astro-paper
# 在 src/content/posts/ 下新建 .md，然后
git add -A && git commit -m "post: xxx" && git push
```

文件名就是 URL：`posts/hello-world.md` → `/posts/hello-world`。

## 三、手动部署

```bash
cd astro-paper
npm run deploy          # = npm run build && wrangler deploy
```

或者分步：

```bash
npm run build
npx wrangler deploy
```

> Node 版本必须 ≥ 22.12.0。

### 密钥管理

```bash
# 设置或更新（必须用 printf，echo 会把换行写进密钥）
printf '%s' '值' | npx wrangler secret put GITHUB_TOKEN
printf '%s' '值' | npx wrangler secret put ADMIN_PASSWORD

# 查看已设置的密钥名（不含值）
npx wrangler secret list
```

`GITHUB_TOKEN` 用的是**细粒度 PAT**，权限只需要 **Contents: Read and write**，只授权 `li1574/blog` 这一个仓库。令牌过期后发文会返回 `502 Bad credentials`，重新生成并 `secret put` 即可。

## 四、接上 Git 自动构建（必做）

`wrangler` 没有配置 Workers Builds 的命令行接口，必须在 Dashboard 手动接一次。**不接的话，后台发文只是提交了代码，线上永远不会更新。**

Dashboard → **Workers & Pages** → `li1574-blog` → **Settings** → **Build** → **Connect**：

| 配置项 | 值 |
| --- | --- |
| Git repository | `li1574/blog` |
| Production branch | `main` |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Root directory | `/` |

接好之后整条链路才算通：**后台发文 → 提交仓库 → 自动构建 → 上线**。

## 五、域名

`blog.li1574.ccwu.cc` 已生效，返回本站内容。

注意：`ccwu.cc` 的 apex NS 目前仍在 `dnshe.org`，只有这个子域指向 Cloudflare。如果以后要迁整站到 Cloudflare，需要在 Dashboard → Add a site → 按提示去注册商改 NS。

改域名的话要同步三处：

1. `astro-paper.config.ts` 的 `site.url`（影响 canonical / sitemap / RSS）
2. `worker/index.ts` 里 `publish()` 返回的 `url` 字段（纯提示用）
3. Dashboard 里 Worker 的 Domains & Routes

## 六、本地开发

```bash
npm install
npm run dev            # 站点：localhost:4321（没有 /api/*）
npx wrangler dev       # 完整环境：静态资源 + API
```

用 `wrangler dev` 测后台时，把密钥写进 `.dev.vars`（已在 `.gitignore`）：

```
GITHUB_TOKEN=github_pat_xxx
ADMIN_PASSWORD=本地测试口令
```

> `npm run dev` 只有静态页面，后台发文会 404，必须用 `wrangler dev`。
>
> `npm run dev` 里搜索框也搜不出东西，因为 Pagefind 索引只在 `build` 时生成。

## 七、排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后台提示「服务端未配置」 | secret 没设 | `wrangler secret put GITHUB_TOKEN` |
| 后台提示「口令不正确」 | 输错或 secret 刚改 | 重输；确认 `ADMIN_PASSWORD` |
| 发布返回 502 Bad credentials | GitHub 令牌过期或无 Contents 权限 | 重新生成令牌，`printf` 写入 secret |
| 发布成功但线上没更新 | 没接 Workers Builds | 见第四节 |
| 站点 404 | 没构建就部署 | `npm run build` 后再 deploy |
| 搜索无结果 | 索引没生成 | `npm run build` 会跑 Pagefind |
| 构建报 `Unsupported OpenType signature` | 代理拦截本地请求 | 加 `NO_PROXY="localhost,127.0.0.1,[::],::1"` |
| 构建报 `npm ci` 失败 | package.json 与 lock 不同步 | `npm install --package-lock-only` |
| 中文 OG 图是方块 | 动态 OG 已关闭，用静态图 | 改 `public/default-og.jpg`（`node scripts/make-og.mjs` 重新生成） |

## 八、几个设计决定（改之前先看）

**为什么发文走 GitHub 提交而不是数据库**
站点是纯静态的，内容必须进仓库才能被构建。用 D1 存文章还得再写一套渲染逻辑，白白多一层。

**为什么关了动态 OG 图**
satori 只认显式传入的字体，主题自带的 Google Sans Code 没有中文字形，中文标题会渲染成方块。改用静态图后顺带解决了代理环境下 OG 构建失败的问题。

**为什么 OG 图以 base64 存在仓库里**
`scripts/default-og.jpg.b64` + `scripts/prepare-assets.mjs`，`prebuild` 时还原到 `public/default-og.jpg`（已 gitignore）。这样仓库里没有二进制文件，任何构建环境都能跑。

**为什么中文字体走系统回退**
Google Sans Code 只有拉丁字符。`astro.config.ts` 里配了 `PingFang SC / Microsoft YaHei / Hiragino Sans GB / Noto Sans CJK SC` 回退链，不额外下载中文字体（那会是几 MB）。
